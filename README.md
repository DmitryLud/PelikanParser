# PelikanParser

Локальный Windows‑парсер цен по Eurocode для каталога Pelikan Autoglass. Программа входит в личный кабинет, берет коды из Excel, по очереди выполняет поиск и сохраняет отдельный Excel‑файл с минимальной найденной ценой и соответствующим производителем.

Парсер запускается на компьютере пользователя. Публичный адрес сайта и готовые селекторы уже находятся в конфигурации. Логин, пароль, браузерная сессия и рабочие результаты в репозитории не хранятся.

## Что делает программа

```text
input/eurocodes.xlsx
        ↓
чтение и очистка списка Eurocode
        ↓
вход на сайт и последовательный поиск каждого кода
        ↓
извлечение всех карточек, цен и производителей
        ↓
выбор минимальной цены
        ↓
output/results.xlsx
```

Основные правила:

- если найдена одна позиция с ценой, записывается ее цена и производитель;
- если найдено несколько позиций с ценами, выбирается минимальная цена;
- производитель всегда берется из той же карточки, где найдена выбранная цена;
- карточки без цены не участвуют в сравнении цен;
- если цена отсутствует во всех найденных карточках, записывается статус `Нет в наличии`;
- ошибка обработки одного Eurocode записывается в результат, после чего программа продолжает работу со следующим кодом.

Статус определяется по наличию цены, как требовалось для этого сайта. Текст `Наличие на складе` извлекается из карточки как вспомогательная информация, но сам по себе не меняет выбранную цену.

Пример:

| Карточка | Производитель | Цена | Результат |
| --- | --- | ---: | --- |
| 1 | VOLKSWAGEN | 85 000 ₽ | — |
| 2 | FYG* | 49 300 ₽ | выбрано |

В Excel попадут цена `49 300` и производитель `FYG*`.

## Что потребуется на новом компьютере

- Windows 10 или Windows 11;
- Python 3.11 или новее;
- интернет при первой установке зависимостей и Chromium;
- разрешенный доступ к личному кабинету сайта;
- Excel или LibreOffice только для удобного редактирования и просмотра `.xlsx` — самой программе Microsoft Excel не требуется.

Git, Visual Studio Code и другие средства разработки для обычного запуска не нужны. Если проект скачивается ZIP‑архивом с GitHub, достаточно распаковать его в обычную папку.

Не переносите `.venv` с другого компьютера. Виртуальное окружение содержит пути конкретной системы и должно создаваться заново через `setup.bat`.

## Установка на чистый Windows‑ноутбук

### 1. Установите Python

Скачайте Python 3.11 или новее с [python.org](https://www.python.org/downloads/windows/). В установщике оставьте включенным Python Launcher (`py`).

Проверить установку можно в PowerShell:

```powershell
py --version
```

### 2. Скачайте проект

Откройте [репозиторий PelikanParser](https://github.com/DmitryLud/PelikanParser), нажмите `Code` → `Download ZIP` и распакуйте архив. Можно также клонировать репозиторий через Git, но для работы парсера это не требуется.

Не запускайте проект непосредственно внутри ZIP‑архива.

### 3. Выполните автоматическую установку

Запустите `setup.bat` из корня проекта. Он автоматически:

1. создаст локальное окружение `.venv`;
2. установит Python‑зависимости проекта;
3. установит Chromium для Playwright;
4. создаст `config.yaml` из `config.example.yaml`, если файла еще нет;
5. создаст `.env` из `.env.example`, если файла еще нет.

Повторный запуск `setup.bat` не перезаписывает существующие `.env` и `config.yaml`.

После установки обычному пользователю достаточно заполнить `.env`, внести Eurocode в Excel и запустить `run.bat`. Редактировать селекторы или адрес сайта не требуется.

## Первоначальная настройка

### Учетная запись

Откройте созданный файл `.env` и заполните его:

```dotenv
PELIKAN_EMAIL=ваша-почта@example.com
PELIKAN_PASSWORD=ваш-пароль
```

Не добавляйте кавычки без необходимости. Файл `.env` исключен из Git и не должен передаваться другим пользователям вместе с проектом.

### Готовая конфигурация сайта

Проект уже настроен на текущий адрес личного кабинета:

```yaml
site:
  login_url: "https://lk.pelikan-ag.ru/login"
  catalog_url: "https://lk.pelikan-ag.ru/"
```

В конфигурацию также добавлены точные элементы из предоставленного HTML:

- email — `#mail` и `input[name="username"]`;
- пароль — `#password` и `input[name="password"]`;
- кнопка входа — `form button[type="submit"]`;
- поле поиска Eurocode — по постоянному `placeholder="Наименование | еврокод | OEM номер"`;
- карточки, производитель, цена и наличие — по смысловой структуре и подписям HTML.

ID поля поиска вида `base-ui-_r_44_` намеренно не используется: это динамический ID, который может стать другим после обновления сайта или нового запуска.

Файл `config.yaml` требуется менять только в случае изменения адреса или HTML‑разметки сайта.

Для первого запуска рекомендуется оставить:

```yaml
browser:
  headless: false
```

Так будет видно, что делает браузер. После проверки можно переключить значение на `true`.

## Как устроен входной Excel

По умолчанию программа читает файл `input/eurocodes.xlsx`.

Настройки источника находятся в `config.yaml`:

```yaml
input:
  path: "input/eurocodes.xlsx"
  sheet: "Eurocodes"
  column: "Eurocode"
  header_row: 1
  deduplicate: true
```

Это означает:

- используется лист `Eurocodes`;
- заголовки находятся в первой строке;
- коды читаются из столбца с заголовком `Eurocode` без учета регистра;
- данные начинаются со следующей строки;
- пустые ячейки пропускаются;
- при `deduplicate: true` повторяющийся код обрабатывается один раз;
- порядок первого появления кодов сохраняется.

Минимальный пример:

| Eurocode | Примечание |
| --- | --- |
| 2485AGACMUVZ | пример |
| F302AGACHMUW |  |
| 57G845011LNVB |  |

Программа использует только столбец `Eurocode`. Остальные столбцы можно применять для собственных комментариев — они не попадут в результат автоматически.

### Важные особенности Eurocode

- Форматируйте столбец как `Текст`, особенно если код может начинаться с нуля.
- Текстовые значения сохраняются без изменения, кроме пробелов в начале и конце.
- Целое число из Excel преобразуется в текст без окончания `.0`.
- Повторы сравниваются без учета регистра: `ABC123` и `abc123` считаются одним кодом при включенном удалении дубликатов.
- Чтобы обрабатывать повторяющиеся строки отдельно, установите `deduplicate: false`.

Путь, лист, название столбца и строку заголовка можно изменить в `config.yaml` без изменения Python‑кода.

## Полная логика обработки одного Eurocode

Для каждого кода программа выполняет следующие действия:

1. При необходимости очищает предыдущий запрос.
2. Вводит Eurocode в поле поиска каталога.
3. Нажимает кнопку `Поиск`; если кнопка не найдена, отправляет клавишу `Enter`.
4. Ожидает появления карточек или сообщения об отсутствии результатов.
5. Находит каждую товарную карточку `li > article`, содержащую подписи `Производитель:` и `Еврокод:`.
6. Внутри каждой карточки извлекает производителя, наличие и все элементы цены со знаком `₽`.
7. Преобразует цены вида `49 300 ₽`, `49 300 ₽` и `49 300,50 ₽` в числовое значение.
8. Если в одной карточке случайно указано несколько цен, берет минимальную цену внутри этой карточки.
9. Сравнивает цены всех карточек и выбирает общую минимальную.
10. Сохраняет цену вместе с производителем именно выбранной карточки.

Если карточки существуют, но цена отсутствует в каждой из них, результат получает:

- пустую цену;
- пустого производителя;
- статус `Нет в наличии`;
- комментарий `У найденных позиций цена не указана`.

Если карточки вообще не найдены, статус также будет `Нет в наличии`, а комментарий — `Позиции не найдены`.

## Запуск

### Проверка локальных настроек

Перед первым входом на сайт выполните:

```powershell
.venv\Scripts\python -m pelikan_parser check --config config.yaml --env .env
```

Команда проверяет конфигурацию, наличие входного Excel, лист, заголовок столбца и количество кодов. Сайт при этом не открывается.

### Проверка одного кода в видимом браузере

```powershell
.venv\Scripts\python -m pelikan_parser run --config config.yaml --env .env --limit 1 --headful
```

Это наиболее безопасный способ проверить новый компьютер и настройки сайта.

### Обычный запуск

Запустите `run.bat` или выполните:

```powershell
.venv\Scripts\python -m pelikan_parser run --config config.yaml --env .env
```

Перед запуском закройте `output/results.xlsx`, если он открыт в Excel. Каждый новый запуск перезаписывает этот файл.

## Результат

По умолчанию результат сохраняется в `output/results.xlsx` на листе `Результат`.

Основные столбцы:

| Столбец | Значение |
| --- | --- |
| `Eurocode` | исходный код из входного файла |
| `Цена` | минимальная найденная цена; в Excel хранится как число |
| `Производитель` | производитель карточки с минимальной ценой |
| `Статус` | `В наличии`, `Нет в наличии` или `Ошибка` |

При `output.include_diagnostics: true` добавляются:

| Столбец | Значение |
| --- | --- |
| `Найдено позиций` | количество уникальных карточек результата |
| `Позиций с ценой` | количество карточек, в которых удалось получить цену |
| `Комментарий` | причина отсутствия цены или текст ошибки |

Диагностические столбцы можно отключить:

```yaml
output:
  include_diagnostics: false
```

Путь результата также можно изменить через `output.path`.

## Настройка элементов сайта

В `config.example.yaml` уже записаны селекторы входа, поиска, карточек, производителя, цены и наличия по предоставленной HTML‑разметке. Они опираются на постоянные атрибуты и подписи полей, а не на длинные Tailwind‑классы или динамические ID.

Для каждого элемента можно задать несколько вариантов. Программа проверяет их сверху вниз и использует первый найденный:

| Поле | Назначение |
| --- | --- |
| `selectors.login.email` | поле электронной почты |
| `selectors.login.password` | поле пароля |
| `selectors.login.submit` | кнопка входа |
| `selectors.login.success_marker` | необязательный признак успешного входа |
| `selectors.catalog.search_input` | поле поиска |
| `selectors.catalog.search_submit` | кнопка поиска |
| `selectors.catalog.clear` | необязательная кнопка очистки |
| `selectors.results.item` | контейнер одной карточки |
| `selectors.results.manufacturer` | производитель внутри карточки |
| `selectors.results.price` | цена внутри карточки |
| `selectors.results.availability` | информация о наличии |
| `selectors.results.expand` | необязательная кнопка раскрытия карточки |
| `selectors.results.empty` | сообщение об отсутствии результатов |

Поддерживаемые форматы локаторов:

```yaml
- "css=.catalog-card"
- "xpath=.//p[contains(normalize-space(.), '₽')]"
- "placeholder=Адрес электронной почты"
- "label=Электронная почта"
- "text=Поиск"
- "role=button|Вход"
- "testid=search-button"
```

Если разметка сайта изменится, запустите обработку одного кода с `--headful`, затем изучите HTML и снимок из папки `debug`.

## CAPTCHA и ручное подтверждение входа

Если сайт запрашивает CAPTCHA или одноразовый код:

```yaml
browser:
  headless: false
  manual_login_timeout_seconds: 120
```

После отправки логина и пароля программа будет ждать до 120 секунд, чтобы пользователь завершил вход вручную.

Успешная сессия сохраняется в `.session/state.json`. Файл исключен из Git. Если сессия устарела и вход работает неправильно, закройте программу, удалите локальную папку `.session` и войдите заново.

## Диагностика ошибок

При ошибке входа или отдельного поиска программа может сохранить в папку `debug`:

- PNG‑снимок текущей страницы;
- HTML страницы.

Настройка:

```yaml
debug:
  save_on_error: true
  directory: "debug"
```

HTML и снимки могут содержать данные личного кабинета. Не публикуйте папку `debug` и не пересылайте ее без проверки содержимого. Папка исключена из Git.

## Основные настройки браузера

| Параметр | Назначение |
| --- | --- |
| `headless` | скрывать или показывать браузер |
| `timeout_ms` | общее время ожидания элемента |
| `results_timeout_ms` | время ожидания результатов поиска |
| `after_search_delay_ms` | дополнительная пауза после поиска |
| `after_expand_delay_ms` | пауза после раскрытия карточки |
| `delay_between_codes_ms` | интервал между запросами |
| `storage_state_path` | файл сохраненной браузерной сессии |
| `manual_login_timeout_seconds` | время для ручного входа |

Не уменьшайте `delay_between_codes_ms` без необходимости. Интервал снижает нагрузку на сайт и вероятность временной блокировки.

```text
PelikanParser/
```

## Команды для разработчика

```powershell
# Создать .env и config.yaml из примеров
.venv\Scripts\python -m pelikan_parser init

# Запустить все тесты
.venv\Scripts\python -m unittest discover -s tests -v

# Показать справку
.venv\Scripts\python -m pelikan_parser --help
```

Тесты проверяют разбор цен, знак `₽`, выбор минимальной цены вместе с производителем, отсутствие цены, чтение и запись Excel, вход и поиск в локальной имитации сайта.

## Безопасность

- Используйте автоматизацию только для учетной записи и сайта, к которым у вас есть разрешенный доступ.
- Не добавляйте `.env`, `.session` и `debug` в Git.
- Не передавайте пароль вместе с проектом.
- Перед передачей диагностического HTML проверьте, нет ли в нем персональных данных.
- Репозиторий содержит только `.env.example` с фиктивными значениями.
